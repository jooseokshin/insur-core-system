# 실손의료보험 보상과 대외기관 연계

- 작성일: 2026-11-09
- 대상: V26 실손의료보험(보험종목 05) 상품, 4세대 보상 계산, 한국신용정보원 연계, 보험개발원 실손 청구 전산화(실손24) 수신
- 성격: 구현 설명과 근거 정리다. **법률 의견이 아니고, 요율·한도·전문 규격은 실제 값이 아니다.** 어떤 값이 확인된 사실이고 어떤 값이 예시인지 표로 나눴다.
- 출처 표기: **[공식]** 정부·공공기관 발표, **[보도]** 언론·법무법인 자료. 보도는 원문으로 다시 확인해야 한다.

## 1. 왜 실손은 다른 보험과 계산이 다른가

자동차·화재 보상은 "사정 손해액 − 자기부담금"을 담보별로 한 번 계산하면 끝난다. 실손은 세 가지가 다르다.

| 차이 | 내용 | 시스템에 생긴 것 |
|---|---|---|
| 청구 근거가 영수증 | 진료비 영수증 한 장(진료일·의료기관 1회)마다 공제를 따로 한다. 같은 금액이라도 영수증 3장이면 공제가 3번이다 | 진료 내역 표 `TB_CLM_MED_ITEM`, 접수 API 의 `medicalItems` |
| 공제가 정률과 정액 중 큰 쪽 | 급여 20%·비급여 30%와, 통원은 최소 공제(급여 의원·병원 1만원, 종합·상급종합 2만원, 비급여 3만원) 중 큰 금액 | 상품별 규칙 표 `TB_PRD_MED_RULE`, `MedicalClaimCalculator` |
| 여러 개 들어도 더 받지 못함 | 실제 쓴 의료비를 메우는 손해보험이라 이득을 보면 안 된다(이득 금지). 실손이 둘이면 손해액을 책임액 비율로 나눈다(비례보상) | 신용정보원 조회, 비례보상 표 `TB_CLM_MED_SHARE` |

### 계산식 (구현 그대로)

```
진료 1건, 담보별:
  공제 = max(최소 공제, ⌈의료비 × 자기부담률⌉)  (의료비를 넘지 않음, 의료비 0이면 0)
  책임액 = 의료비 − 공제                        (통원은 1회 한도까지)
담보별 합계 책임액 L
비례보상: 다른 계약 책임액 L_j 가 있으면 손해액 C = max(L, L_j...)
  Σ ≤ C 이면 각자 L, 아니면 우리 분담 = ⌊C × L ÷ Σ⌋
지급액 = min(분담액, 남은 연간 한도)
```

손 계산 예 (테스트 `MedicalClaimCalculatorTest`, `MedicalIndemnityIntegrationTest` 와 같은 값):

| 진료 | 급여 → 공제 → 책임액 | 비급여 → 공제 → 책임액 |
|---|---|---|
| 의원 통원 | 30,000 → max(1만, 6,000)=10,000 → 20,000 | 50,000 → max(3만, 15,000)=30,000 → 20,000 |
| 종합병원 통원 | 150,000 → max(2만, 30,000)=30,000 → 120,000 | 400,000 → 120,000 → 280,000 → **1회 한도 200,000** |
| 상급종합 입원 | 1,000,000 → 200,000 → 800,000 | 2,000,001 → ⌈600,000.3⌉=600,001 → 1,400,000 |
| 합계 | **940,000** | **1,620,000** |

같은 규칙의 다른 보험사 실손이 1건 있으면 급여 940,000 × 940,000 ÷ 1,880,000 = 470,000, 비급여 810,000 으로 절반씩 낸다.

### 확인된 값과 예시 값

| 항목 | 이 시스템의 값 | 근거 |
|---|---|---|
| 자기부담률 급여 20%·비급여 30% | 그대로 사용 | 4세대 구조 [보도: [비즈워치 2021](https://news.bizwatch.co.kr/article/finance/2021/06/30/0016)], [공식: [금융위원회](https://fsc.go.kr/po010102/76157?curPage=37)] |
| 통원 최소 공제 1만·2만·3만원 | 그대로 사용 | 같은 자료 |
| 연간 한도 급여·비급여 각 5천만원 | 가입금액 5천만원으로 고정 | 같은 자료. **합산 한도로 설명하는 자료도 있어 상품 약관으로 확인해야 한다** |
| 통원 1회 한도 20만원 | 예시 | 검색으로 확인하지 못함. 약관 값으로 바꿔야 한다 |
| 보험료율·나이 계수 | 예시 (개발용) | 실제 요율이 아니다 |
| 다른 회사 책임액 = 우리 계산 | 단순화 | 실무에서는 계약 세대(1~4세대)마다 공제가 달라 회사별로 다시 계산한다 [보도: [뉴시스 2024](https://www.newsis.com/view/NISX20240321_0002669273)] |
| 4세대 비급여 차등(할인·할증), 3대 비급여 특약 | 구현하지 않음 | 범위 밖 |

## 2. 한국신용정보원 연계를 왜 하나

신용정보원은 보험회사들이 계약·지급 정보를 모으는 집중기관이다. 실손에서는 두 방향으로 쓴다.

| 연계 | 언제 | 왜 해야 하나 | 구현 |
|---|---|---|---|
| **중복가입 조회** (Q001) | 청약 접수 | 실손을 이미 가진 고객이 하나 더 들면 보험료만 더 내고 보상은 늘지 않는다(비례보상). 판매할 때 확인하고 설명해야 한다. 개인신용정보 조회라서 **동의가 먼저** 있어야 한다 | 동의 없으면 E-MED-001. 결과는 `TB_CTR_MED_CHECK` |
| **비례보상 조회** (Q001) | 손해사정 | 사고 시점에 다른 회사 실손이 있는지 알아야 우리 분담액을 정한다. 모르면 과지급(다른 회사와 중복 지급) | 손해사정 중 조회, 장애면 E-MED-004 |
| **계약정보 집중** (R001) | 승인·해지 | 다른 회사가 우리 고객을 조회할 때 우리 계약이 보여야 그 회사의 중복 확인·비례보상이 맞는다. 업계 공동 정보라 한 회사가 빠지면 모두의 계산이 틀린다 | 대기열(아웃박스)에 쌓아 보냄 |
| **지급정보 집중** (R002) | 보험금 지급 | 보험사기 분석과 중복 청구 확인에 쓰인다 | 대기열 |

### 장애가 났을 때 업무를 어떻게 하나 (실무에서 가장 많이 묻는 부분)

대외기관은 우리가 통제할 수 없다. 기관이 멈췄을 때 업무를 멈출지, 계속하고 나중에 맞출지를 업무마다 정해야 한다.

| 업무 | 기관 장애 시 | 이유 |
|---|---|---|
| 청약 접수 | **받는다** (조회 상태 80) | 고객을 돌려보내면 판매 기회를 잃는다. 조회는 나중에 해도 된다 |
| 승인 | **막는다** (E-MED-003, 다시 조회해야 함) | 중복 확인 없이 계약이 성립하면 설명 의무를 지키지 못한다 |
| 손해사정 | **막는다** (E-MED-004, 503) | 비례보상을 모른 채 계산하면 과지급. 지급은 되돌리기 어렵다 |
| 계약·지급정보 집중 | **업무는 끝내고 나중에 보낸다** | 보고는 업무의 결과다. 기관 때문에 승인·지급이 실패하면 안 된다 |

"나중에 보낸다"를 안전하게 하는 방법이 **트랜잭셔널 아웃박스**다(`TB_EXT_OUTBOX`, `OutboxService`, `OutboxSender`).

- 업무 거래 안에서 전문을 표에 쌓기만 한다. 업무가 롤백되면 전문도 사라지고, 커밋되면 반드시 남는다. "보냈는데 업무는 없는" 상태와 "업무는 됐는데 안 보낸" 상태가 둘 다 생기지 않는다.
- 별도 작업이 10초마다 보낸다. `FOR UPDATE SKIP LOCKED` 로 집어서 서버가 여러 대여도 같은 건을 두 번 보내지 않는다.
- 실패하면 30초 × 2^(n−1) 뒤(최대 1시간)로 미룬다. 장애 중인 기관을 계속 두드리면 회복이 늦어진다.
- 5번 실패하면 멈춤(90)으로 두고 운영자가 원인을 본 뒤 `/api/admin/ext/outbox-retry` 로 다시 보낸다. 전문 자체가 틀린 경우 끝없이 재시도하지 않게 한다.
- 다시 보낼 때 **같은 추적번호**를 쓴다. 기관이 받았는데 응답만 잃은 경우 기관이 중복을 가려낼 수 있어야 한다.

### 전문(고정길이 메시지)

대외기관 연계는 아직 JSON 보다 **바이트 고정길이 전문**이 흔하다. `FixedLengthCodec` 이 다음 규칙을 지킨다.

- 길이는 글자가 아니라 **기관 문자셋(MS949) 바이트**로 센다. 한글은 2바이트라 "실손"은 4바이트다.
- 숫자는 앞을 0, 문자는 뒤를 공백으로 채운다. 넘치면 거절하고, 상품명 같은 글 항목만 한글을 반으로 자르지 않고 줄인다.
- 공통부(전문 길이, 전문 종별 0200/0210, 거래 구분, 기관 코드, 거래 일시, 추적번호 20자리, 응답코드) + 개별부(+ 반복부). 응답은 종별·거래·추적번호가 요청과 같아야 받는다.

**배치(`KcisLayouts`)는 이 프로젝트가 정한 것이며 실제 신용정보원 규격이 아니다.** 실제 규격은 기관과 맺은 연계 명세서로만 받을 수 있다. 실제 연계로 바꿀 때는 `KcisLayouts` 의 항목과 통로(`KcisTransport`, 지금은 모의 기관 `KcisSimulator`)만 바꾸면 되도록 나눠 두었다. 운영에서는 `KCIS_MODE` 를 바꾸고 실제 통로 구현(전용선·VPN 위의 TCP 또는 HTTPS)을 더해야 한다. 지금은 모의 기관만 있으므로 `simulator` 가 아니면 기동이 실패한다.

모의 기관으로 장애를 흉내 내는 방법: 피보험자 ID 가 `ERR` 로 시작하면 시간 초과, `BAD` 로 시작하면 오류 응답 E101. 피보험자 `DUP-001` 은 다른 보험사(K11) 실손이 있다(비례보상 확인용).

## 3. 보험개발원 실손 청구 전산화(실손24)를 왜 받나

| 항목 | 내용 |
|---|---|
| 무엇 | 환자가 요청하면 의료기관이 실손 청구 서류를 전자로 보내고, 보험개발원이 중계해 보험회사로 넘긴다 |
| 근거 | 보험업법 개정. 병원급은 2024-10-25, 의원·약국은 2025-10-25 부터 [보도: [법무법인 대륜](https://www.daeryunlaw.com/newsletter/news/77)], [공식: [복지로](https://www.bokjiro.go.kr/ssis-tbu/cms/pc/news/promotion/1307392_1118.html)], 참여 현황 [보도: [메디게이트뉴스](https://medigatenews.com/news/1238929545)], [보도: [서울시 미디어허브](https://mediahub.seoul.go.kr/archives/882826)] |
| 보험회사 쪽 일 | 종이·사진을 받아 다시 입력하던 일 대신, 중계에서 오는 청구를 받아 사고로 접수해야 한다. 소액 청구를 포기하던 고객이 청구하게 되므로 건수가 늘어날 것을 대비해야 한다 |

구현 (`/api/ext/kidi/medical-claim`, `KidiClaimService`):

- 호출자는 사람이 아니라 기관 서버다. 인증 서버에 대외기관 클라이언트(`app.oauth.partners[n]`, client credentials)로 등록하고 토큰에는 `EXTERNAL` 역할만 들어간다. 코어는 이 역할에 수신 API 하나만 열고, 나머지는 직원 전용 기본 규칙으로 막힌다.
- 중계 전송번호로 한 번만 접수한다(사고 거래 UUID = `KIDI-` + 전송번호). 중계가 응답을 못 받고 다시 보내면 같은 사고를 돌려주고, 같은 번호에 다른 내용이면 거절한다(E-CLM-009).
- 피보험자의 실손 계약 중 첫 진료일을 보장하는 계약을 찾는다. 없으면 E-KIDI-002, 둘 이상이면 자동으로 고르지 않는다(E-KIDI-003, 담당자 확인).
- 접수 뒤로는 직원 접수와 같다. 진료 내역의 경로만 `KIDI` 로 남고 화면에 "실손24" 표시가 붙는다.
- 실제 연계는 주민등록번호로 피보험자를 찾고 서류 이미지(영수증, 세부내역서)도 받는다. 이 시스템은 고객 ID 와 금액만 받는다.

## 4. 이 구현에 없는 것 (실무로 가려면 더 해야 하는 일)

- 실제 기관 규격 전문과 통로(전용선, 기관 인증서, 전문 암호화)
- 피보험자 식별: 주민등록번호 암호화 저장과 조회(고유식별정보 처리 근거)
- 신용정보 조회 동의서 원문 보관과 동의 철회 처리, 갱신 때 재동의 정책 (지금은 갱신이 원 계약 동의를 잇는다)
- 1~3세대 실손 상품의 다른 공제 규칙, 회사별 책임액 계산
- 4세대 비급여 보험료 차등(직전 1년 비급여 지급액에 따른 할인·할증)
- 서류 이미지 수신과 보관, 의료자문·현장조사 같은 손해사정 절차
- 대기열 운영 화면 (지금은 API 만 있음: `outbox-list`, `outbox-retry`)
