# 보험료 자동이체 (금융결제원 CMS 출금이체)

- 작성일: 2026-11-13
- 대상: V30, 자동이체 등록 API(`/api/contract/autodebit/*`), 배치 `cmsDebitJob`
- 성격: 구현 설명과 근거. **파일 배치·결과코드·이용기관 코드는 실제 결제원 규격이 아니다.** 파일 이름 EB21(출금 의뢰)·EB22(출금 결과)는 공개 교육 자료에서 확인했고, EB11·EB12(등록 의뢰·결과)는 확인하지 못해 이 프로젝트가 붙인 이름이다.

## 왜 필요한가

지금까지 보험료는 직원이 수납 화면에서 현금·카드·이체로 입력했다. 실제 보험사는 계속보험료와 갱신보험료 대부분을 고객 계좌 자동이체로 받는다.
금융결제원 CMS 는 이용기관(보험사)과 여러 은행 전산을 이어 고객 계좌에서 출금할 수 있게 하는 서비스다 [자료: [하나은행 CMS 안내](https://kebhana.com/cont/info/info03/info0309/index.jsp)].
흐름은 "신규(출금 동의) 등록 → 출금 청구 → 청구 결과" 순서다 [자료: [도너스 교육 자료](https://knowledge.donus.org/hc/ko/article_attachments/28337307179545)].

## 출금 동의

| 항목 | 이유 | 구현 |
|---|---|---|
| 동의는 예금주에게서 | 돈이 나가는 계좌의 주인이 동의해야 한다. 계약자와 달라도 된다(가족 계좌) | 등록할 때 은행 예금주 조회로 예금주가 입력한 이름과 같은지 확인 (E-CMS-003) |
| 동의 방식과 증빙 | 지급인 동의는 서면 또는 녹취 등 금융위원회가 정한 방법으로 받는다 (전자금융거래법 시행령 제10조) [자료: [korea.legal 정리](https://korea.legal/wiki/%ea%b3%84%ec%a2%8c%c2%b7%ec%b9%b4%eb%93%9c-%ec%9e%90%eb%8f%99%eb%82%a9%eb%b6%80%eb%a5%bc-%ec%a1%b0%ed%9a%8c%ed%95%98%ea%b3%a0-%ed%95%b4%ec%a7%80%c2%b7%eb%b3%80%ea%b2%bd%ed%95%98/)]. 2014년 CMS 부당 인출 사건 뒤 등록 단계의 동의 확인이 강화됐다 [보도: [보안뉴스](https://m.boannews.com/html/detail.html?idx=39856)] | 방식(서면·녹취·ARS·전자서명)과 증빙 관리번호를 남긴다. 증빙 원본 보관과 보관 기간은 이 시스템 밖 (확인하지 못함) |
| 계좌번호 | 결제원 파일에 평문으로 넣어야 하므로 복호화 가능한 암호화 | AES-256-GCM (`ACCOUNT_ENC_KEY`), 화면은 마스킹 |
| 계약당 하나 | 두 계좌에서 같은 보험료가 나가지 않게 | 살아 있는 등록(대기·의뢰·완료)은 계약당 하나 |
| 갱신 승계 | 갱신할 때마다 고객에게 동의를 다시 받지 않게 | 원 계약의 완료된 등록을 이어받고, 납부자번호(증권번호)가 바뀌므로 결제원에는 새로 등록 의뢰 |

## 배치 (`cmsDebitJob`, 출금일 기준, 매일 07:00)

```
1 등록 의뢰 (EB11)   등록 대기 → 의뢰함
2 등록 결과 (EB12)   의뢰함 → 등록 완료 / 등록 불능(계좌 해지·지급정지·예금주 불일치)
3 출금 대상 선정      청약 계약 + 등록 완료 + 남은 보험료 > 0 + 진행 중 출금 없음 + 실패 3번 미만 + 이 출금일에 아직 시도 안 함
4 출금 의뢰 (EB21)   의뢰 대상 → 결과 대기
5 출금 결과 (EB22)   성공 → 수납(CMS) 기록 / 실패(잔액 부족 등) → 다음 출금일에 최대 3차까지 재출금
```

| 설계 | 이유 |
|---|---|
| 파일 꼬리 레코드(건수·합계)를 데이터와 맞춰 보고 다르면 받지 않는다 | 파일 전송 중 잘림·중복은 실제로 생긴다. 합계가 틀린 파일로 수납을 반영하면 되돌리기 어렵다 |
| 출금일당 한 번만 완료, 실패하면 **실패한 단계부터** 재시작 | 결과 파일이 늦게 오면 2·5 단계가 실패한다. 다시 실행해도 이미 보낸 의뢰 파일을 또 보내지 않는다(이중 출금 방지). 스프링 배치가 완료한 단계를 건너뛴다 |
| 출금 결과를 기다리는 동안 수기 수납 금지 (E-CTR-031) | 결과가 오기 전에 창구에서 또 받으면 과납이 되고 환불이 생긴다 |
| 출금 진행 중 해지 금지 (E-CMS-005) | 이미 의뢰한 출금은 결과까지 처리해야 한다 |
| 직원 수납 API 는 CMS 를 받지 않는다 | 자동이체 수납은 배치만 결제원 결과로 남긴다 |
| 출금된 돈은 계약이 취소됐어도 수납으로 남긴다 | 돈은 이미 들어왔다. 환불은 별도 절차 |

실무에서는 의뢰와 결과 사이가 하루 이상이라 의뢰 작업과 결과 작업을 나누고, 출금일은 영업일 기준이다. 이 구현은 한 작업으로 두고 영업일 계산을 하지 않는다.

## 넣지 않은 것

- 해지를 결제원에 통보(해지 의뢰 파일), 은행 창구에서 들어온 신청·해지 통보 처리
- 증빙 원본(신청서 이미지·녹취 파일) 보관과 결제원 증빙 등록
- 분납(월납) 보험료 스케줄 — 지금은 청약 보험료(일시납·잔액)만 출금
- 영업일 달력, 출금 결과 통지(문자) , 미납 안내
