# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Tests

Spring Boot 4 splits the test slices out of the old monolithic `spring-boot-starter-test` into `spring-boot-starter-data-jpa-test` and `spring-boot-starter-webmvc-test`, so slice annotations (`@DataJpaTest`, `@WebMvcTest`) live in modularized packages that differ from Boot 3.

## Configuration

`application.properties` points the datasource at the docker-compose Postgres by default. You can override it with the `DB_URL`, `DB_USERNAME` and `DB_PASSWORD` environment variables. Because the app connects to a real database, `bootRun` and the `@SpringBootTest` `contextLoads` test both need `docker compose up -d` first. The DB runs in Asia/Seoul time and Hibernate's `jdbc.time_zone` matches it, so keep the two consistent. `main` also forces the JVM default time zone to Asia/Seoul, because Hibernate converts `LocalDateTime` through the JVM zone before applying `jdbc.time_zone` (a UTC JVM would store timestamps 9 hours off), and the `test` task runs in that zone too. Timestamps and numbering years come from the injected business `Clock` bean (`BusinessClockConfig`), not `LocalDateTime.now()`.

All endpoints require a JWT Bearer token (HS256, verified with `app.jwt.secret`). The secret comes from the `JWT_SECRET` environment variable, has no default, and must be at least 32 bytes, so `bootRun` fails without it. The token's `sub` claim becomes the request's `empId` and overrides whatever the client sent in the message header. For local runs without exporting it (e.g. from an IDE), activate the `local` profile (`SPRING_PROFILES_ACTIVE=local`, or Active profiles in the IDE run configuration): `application-local.properties` overrides only `app.jwt.secret` with a public dev-only key (`${JWT_SECRET:<dev key>}`, so a real `JWT_SECRET` still wins), and everything else comes from `application.properties`. Never activate `local` in production. The `test` task injects its own `JWT_SECRET` in `build.gradle`. Roles come from the token's `roles` claim (string array: `AGENT`, `UNDERWRITER`, `OPERATOR`, `ADMIN`, mapped to `ROLE_` authorities). Per-API roles are URL rules in `SecurityConfig`, and the target-status check for `/status-change` is `ContractAccessPolicy`. Data-level scope: a caller whose only role is `AGENT` can inquire only contracts they received (`REG_EMP_ID` = token `sub`); other callers see all, and a contract outside the scope answers exactly like a missing one (404 `E-CTR-010`). Premium quotes (`POST /api/premium/quote`) compute `isrdAmt × annual rate × days ÷ 365` from the `TB_PRM_RATE` table, whose seeded rates (V7) are sample values for development, not a real tariff; change them with a new migration. `POST /api/contract/apply` verifies each coverage `prem` against that same calculation for new applications (E-CTR-020; replays of an already-accepted `globalTxId` skip the check), so test data and clients must use premiums consistent with the rate table. Rating factors (`TB_PRM_FACTOR`, optional `rating` input: `driverAge`, `discountGrade`, `structureGrade`) multiply the base rate, and rates/factors are effective-dated (`EFF_FROM`..`EFF_TO` inclusive, looked up by the policy start date): to revise a tariff, close the old row's `EFF_TO` and add a new row in a new migration; a trigger rejects overlapping periods. Termination (`status-change` to 30) records the termination date and a pro-rata refund premium; `/endorse` changes the policyholder/insured of a contract in status 10 or 20 and keeps an audit row per changed field. Payment: `POST /api/contract/payment` (OPERATOR/ADMIN) records a payment on a status-10 contract (installments allowed, `TB_CTR_PAYMENT`, V18; overpaying the remaining premium is E-CTR-027, idempotent per `globalTxId`), and `status-change` to 20 (approval) is rejected with E-CTR-028 until the paid total reaches the contract's total premium; tests that approve contracts must pay in full first. `POST /api/contract/payment-history` lists payments with the paid/remaining totals. `status-change` and `endorse` are idempotent per (contract, `globalTxId`): a replay returns the first result and a different request under the same id is E-CTR-019. The tariff is managed through `/api/admin/premium/{rate,factor}-{list,revise}` (list: UNDERWRITER/OPERATOR/ADMIN, revise: ADMIN only): a revise closes the latest row at `effFrom - 1` and inserts the new row, the new start date must be today (Seoul) or later and after the latest row's start, every change is written to `TB_PRM_AUDIT`, and a replay of the same `globalTxId` returns the first result. `/api/admin/premium/audit-list` (UNDERWRITER/OPERATOR/ADMIN) pages through `TB_PRM_AUDIT`, newest first, filtered by targetType, targetKey prefix, empId and a Seoul-date range. `POST /api/contract/renew` (AGENT own contracts / ADMIN) renews an in-force (20) contract from 60 days before its end date through the end date: it creates a new application (status 10) starting at the old end date with the same term, parties and coverages, re-quotes premiums at renewal time (rating from the request, else the old contract's stored values), and links it through `RENEWED_FROM`; a partial unique index (V17) allows one non-cancelled renewal per contract (E-CTR-025), and replays of the same `globalTxId` return the first result. `POST /api/contract/renew-quote` previews the same renewal (same checks, roles and quote, nothing saved) with the premium difference against the old contract. API docs come from springdoc (`build.gradle`, version 3.x for Boot 4): Swagger UI at `/swagger-ui.html` and the spec at `/v3/api-docs` are open without a token (GET only, `SecurityConfig`), the Authorize button takes a Bearer token from `scripts/dev-token.sh`, they are off by default (`springdoc.*.enabled=${API_DOCS_ENABLED:false}`), the `local` profile turns them on, and elsewhere `API_DOCS_ENABLED=true` is needed. Field descriptions come from `@Schema(description = ...)` on every DTO field and endpoint summaries from `@Operation`/`@Tag` on the controllers; when you add a DTO field or endpoint, keep the javadoc and the annotation text in sync. `scripts/dev-token.sh [empId] [ttlSeconds] [roles]` issues a local dev token (roles default to `ADMIN`). `scripts/e2e-check.sh [--cleanup]` runs an end-to-end check (auth, roles, apply, inquiry, status change, history) against a running app with the same `JWT_SECRET`; it writes real rows to the dev DB, so use `--cleanup` to remove them.

## Schema migrations

Flyway owns the schema. Migrations go in `src/main/resources/db/migration` as `V<n>__<description>.sql` and run automatically at startup. Hibernate is set to `ddl-auto=validate`, so every entity change needs a matching migration or the app fails on startup. Never edit a migration that has already been applied; add a new one instead. Boot 4 only auto-configures Flyway through `spring-boot-starter-flyway`, so don't swap it for bare `flyway-core`. `flyway-database-postgresql` is required for Postgres support.

## Premium rating policy

`PremiumService.quote` requires the rating factors marked required in `TB_PRM_FACTOR_POLICY` (effective-dated by 보험시기, managed via `/api/admin/premium/policy-list|policy-revise`, ADMIN to revise). Missing ones fail with `E-PRM-005`, in both quote and apply. Sample seed: car DRIVER_AGE + DISCOUNT_GRADE, fire STRUCTURE_GRADE, so test/e2e requests need a neutral rating (age 35 / grade 3 = factor 1.0). `scripts/e2e-check.sh --cleanup` restores the seeded policy rows.
